# Курс «Мой огород»

Курс на русском языке для начинающих огородников. Три категории по 13 тем, каждая тема содержит 20 вопросов, каждый вопрос — 10 вариантов и ровно один правильный ответ. Итого: 39 тем, 780 вопросов, 7 800 вариантов.

- `course.md` — полный читаемый банк вопросов с вариантами и отмеченными правильными ответами, оглавлением и источниками.
- `course.json` — полный структурированный банк для загрузки, UTF-8, `format_version: 1`. Иерархия: `categories → topics → questions → answers`. Правильность задаёт логическое поле `is_correct`.
- `source.txt` — редактируемые авторские пары «вопрос|правильный ответ», сгруппированные по категориям и темам.
- `build.py` — воспроизводимая сборка JSON и Markdown средствами стандартной библиотеки Python. Неверные варианты выбираются из банка ответов той же темы; порядок детерминирован. В итоговом JSON все варианты уже записаны, миграция ничего не генерирует. Каждая позиция правильного ответа встречается 78 раз во всём курсе.

Файл содержит вопросы по понятиям, распознаванию признаков, практическим решениям и расчётам. Сроки садовых работ не привязаны к одному региону. Арифметические задания не являются нормами внесения удобрений. Применение средств определяется местной регистрацией и этикеткой конкретного продукта. Источники перечислены для проверки принципов и дальнейшего чтения; иностранные рекомендации не устанавливают разрешения на препараты для России.

## Загрузка

Миграция `m260915_000001_create_moy_ogorod_course` добавляет строку `course` с alias `moy_ogorod`, отдельный тип вопроса с оценкой 1 и пять таблиц:

| Таблица | Строк |
| --- | ---: |
| `course_moy_ogorod_category` | 3 |
| `course_moy_ogorod_topic` | 39 |
| `course_moy_ogorod_question` | 780 |
| `course_moy_ogorod_answer_option` | 7 800 |
| `course_moy_ogorod_question_topic` | 780 |

Структура соответствует `course_sample_*`, включая внешние ключи, индексы и ограничение `is_correct`. Идентификаторы курса и типа вопроса выделяет БД; локальные идентификаторы категорий, тем и вопросов сохраняются из файла. Источники и метаданные остаются в JSON, цели тем загружаются в `topic.description`.

После применения исходных миграций проекта: `php yii migrate --interactive=0`. Для уже применённой миграции повторный запуск команды ничего не добавит. Прямой повторный вызов загрузки либо конфликт alias, типа или таблиц останавливает работу до изменений.

Миграция использует `up()`/`down()`: MySQL автоматически фиксирует DDL, поэтому вставка всех данных выполняется отдельной транзакцией после создания таблиц. При обычной ошибке импорта вставки откатываются, а созданные этим запуском таблицы удаляются. Аварийное завершение процесса/сервера во время DDL может потребовать ручной проверки частично созданной схемы.

Откат удаляет только этот курс, его тип и набор таблиц. До удаления проверяются внешние связи: при подписках или другом использовании курса/типа откат останавливается. Выполняйте миграции последовательно, без параллельных изменений схемы.

Курс не переключает существующие модели, тесты и API с `course_sample_*` на динамические таблицы: это отдельная интеграция приложения. Набор `course_moy_ogorod_*` здесь создан и заполнен непосредственно миграцией.

## Изменение материалов и проверки

До первой загрузки можно изменить `source.txt` и выполнить `python data/courses/moy_ogorod/build.py`, затем проверить результат в `course.md`. После выпуска не меняйте уже применённые исходные данные миграции: корректировки в БД оформляйте новой миграцией.

- `php tests/moy-ogorod.php` проверяет структуру файла, точное содержимое в MySQL, количество строк, позиции ответов, префиксы таблиц, конфликты, уборку после сбоя и защищённый откат.
- `php tests/learning-schema.php` проверяет весь набор миграций и обратный откат с остальной схемой проекта.

Обе проверки создают отдельную случайно названную временную базу и удаляют только её после завершения. Учётной записи БД нужны права на создание и удаление тестовой базы; тест сбоя также использует триггер в этой временной базе.
