# Admin API

Внешний Yii-модуль, не связанный с внутренним фреймворком core.

## Вход

`POST /admin/auth/login` с `Content-Type: application/json`:

```json
{"username":"your-login","password":"your-password"}
```

Для входа по email вместо username передайте `{"email":"user@example.com","password":"your-password"}`.
Передавайте ровно один идентификатор: username или email. Email ищется без учета регистра.
Фронтенд NLAdmin использует только email, API сохраняет оба способа входа.

Ответ 200:

```json
{"auth_key":"generated-token","token_type":"Bearer","user":{"id":1,"username":"your-login"}}
```

Передавайте возвращенный `auth_key` в заголовке `Authorization: Bearer generated-token`.
`GET /admin/auth/me` возвращает только `id` и `username`. `POST /admin/auth/logout` отзывает токен и возвращает `{"success":true}`.

Ошибки возвращаются в JSON: 400 — некорректные входные данные, 401 — неверные реквизиты или токен, 405 — неверный HTTP-метод.
Pretty URL требует настройки веб-сервера на web/index.php. При стандартном разборе пути Yii можно использовать `/index.php/admin/auth/login`.

## Создание пользователя

`POST /admin/auth/create-user` — публичная регистрация без авторизации. Передайте JSON:

```json
{"username":"new-user","password":"new-password"}
```

При регистрации можно добавить `email`, например `"email":"user@example.com"`. Адрес проверяется,
сохраняется в нижнем регистре и должен быть уникальным. Для входа через NLAdmin у пользователя должен быть заполнен email.
Поле добавляется отдельной миграцией `m260912_000002_add_email_to_user`: выполните `php yii migrate`.
У существующих пользователей email остается NULL до заполнения.

Ответ 201 содержит только `id` и `username`. Пароль сохраняется как хеш; токен новому пользователю выдается при отдельном входе.
400 — неверные поля (логин до 100 символов, непустой пароль до 72 байт без нулевых символов),
409 — логин уже занят. Лимит пароля учитывает ограничение bcrypt. Дополнительные поля запроса не записываются.
Метод доступен всем, включая создание первой учетной записи. Отдельного разграничения ролей пока нет.

## Сессия API

Один пользователь имеет один действующий токен. Новый вход отзывает предыдущий. Выход обнуляет auth_key.
В базе хранится SHA-256 хеш токена; исходный токен возвращается только при входе. Токен действует до выхода или следующего входа,
автоматического срока истечения сейчас нет. Передавайте его только по HTTPS за пределами локальной разработки.

Cookies, «Запомнить меня» и CSRF-токен для этих API-запросов не используются. Внешний фронтенд должен отправлять Bearer-заголовок.
CORS обрабатывает OPTIONS; список разрешенных источников настраивается через `modules.admin.corsOrigins` в config/web.php.
По умолчанию разрешены все источники без передачи cookies.

Поле auth_key добавлено в исходную миграцию создания user. Если она уже применена, изменение файла не обновит существующую таблицу:
потребуется отдельная миграция добавления столбца и уникального индекса. Рабочая база автоматически не изменяется.

Текущая таблица не содержит ролей: любой пользователь с верными реквизитами может пройти эту аутентификацию.
Проверка административных прав — отдельная задача, до ее добавления токен не следует считать подтверждением роли администратора.

Проверки на SQLite в памяти: `php tests/admin-auth.php`.
