# Подключения и миграции

`ConnectionManager` получает отдельные подключения через `getConnection('group:db')`, группы через `getGroup('group')`. Настройки групп находятся в `config/db/groups.php`. `ConnectionGroup::iterate()` возвращает независимый обход с `current()`, `key()`, `next()` и `rewind()`.

## Выбор БД в миграции

Команды `migrate/create` и `migrate-course/create` создают стандартные миграции Yii с наследованием от `yii\db\Migration`. Для использования `getConnections()` вручную замените базовый класс на `BaseMigration`, как в примере ниже. Стандартные миграции используют подключение команды.

```php
use app\components\db\BaseMigration;
use app\components\db\ConnectionGroup;

class m260925_120000_add_lesson_status extends BaseMigration
{
    public static function getConnections(): ?ConnectionGroup
    {
        return Yii::$app->dbManager->getGroup('course');
        // Для одной БД: return ConnectionGroup::from(Yii::$app->dbManager->getConnection('course:moy_ogorod'));
    }

    public function safeUp()
    {
        $this->addColumn('{{%lesson}}', 'status', $this->integer()->notNull()->defaultValue(0));
    }

    public function safeDown()
    {
        $this->dropColumn('{{%lesson}}', 'status');
    }
}
```

Если `getConnections()` не переопределён или вернул `null`, используется `--db` (по умолчанию компонент `db`). Без явно переданного `--db` выполняется назначение миграции целиком. Явный `--db` сужает назначение: выбранное подключение должно входить в группу миграции либо совпадать с её одиночным подключением. Иначе команда выбрасывает исключение с именем миграции и подключения до начала выполнения всего набора. Даже `--db=db` считается явным выбором. Для явно выбранной группы каждое её подключение должно быть разрешено миграцией. Проверяется принадлежность объектов подключения, полученных через менеджер/компоненты приложения, а не совпадение DSN.

Статический метод определяет маршрут и не должен выполнять SQL. Контроллер вызывает `$class::getConnections()` без создания экземпляра миграции. Объект создаётся только для выполнения на конкретном подключении; стандартный `init()` Yii сохраняется. `$this->db` при выполнении всегда содержит конкретный `yii\db\Connection`, а в статическом методе `$this` недоступен.

```bash
php yii migrate/create add_lesson_status --migrationPath=@app/migrations/course
php yii migrate --migrationPath=@app/migrations/course --db=course
php yii migrate --migrationPath=@app/migrations/course --db=course:moy_ogorod
php yii migrate/history --migrationPath=@app/migrations/course --db=course
php yii migrate/down 1 --migrationPath=@app/migrations/course --db=course
```

Папка миграций задаётся отдельно от подключения: `migrate` по умолчанию читает `migrations/main`. Для курсов можно использовать `migrate` с `--migrationPath=@app/migrations/course` или короткую команду `php yii migrate-course --db=course:moy_ogorod`.

`migrate-course` использует директорию `migrations/course` и проверяет её перед выполнением. Параметры `--migrationPath`, `--migration-path` и `-p` могут указывать только эту же директорию (эквивалентный абсолютный путь или alias разрешён); другая директория вызывает исключение. Выбор подключения работает так же, как в `migrate`. Для всей группы: `php yii migrate-course --db=course`.

## Выполнение и история

На входе контроллер приводит подключение команды к группе через `ConnectionGroup::from()`: готовая группа сохраняется, одиночное подключение оборачивается в группу из одного элемента. Метод миграции `getConnections(): ?ConnectionGroup` возвращает только группу либо `null` для выбора команды. Для одной БД верните `ConnectionGroup::from($connection)`. Проверка явного `--db` и построение плана работают только с группами; стандартному механизму Yii и экземпляру выполняемой миграции передаётся конкретный `Connection`.

Контроллер сначала обнаруживает все файлы, определяет подключения, затем для каждой БД применяет только назначенные ей миграции в порядке версий. История проверяется в её собственной таблице `migration` (учитываются `tablePrefix` и `--migrationTable`). Числовые ограничения `up`, `down`, `redo`, `new`, `history` применяются отдельно к каждой БД.

После первой ошибки или отказа от подтверждения обход останавливается с ненулевым кодом. Успешные миграции уже находятся в истории соответствующих БД, поэтому повторный запуск пропускает их. Ошибка не добавляется в историю; обработка изменений остаётся в `up()` / `safeUp()` и зависит от СУБД.

Для `down` и `redo` используются текущие назначения миграций. Не удаляйте применённые файлы и не меняйте их `getConnections()` перед откатом: контроллер работает с миграциями из выбранных папок/пространств имён. Между БД общей транзакции нет. Порядок между БД определяется первым появлением подключения при обходе миграций; зависимости между разными БД не рассчитываются.

Доступны все стандартные действия Yii. `redo` повторно применяет миграции; `to` переводит БД к выбранной версии; `mark` меняет только историю; `fresh` удаляет все таблицы выбранных БД и заново применяет назначенный набор миграций. Для `to` и `mark` указанная версия должна существовать в наборе каждого обрабатываемого подключения. Используется стандартная справка Yii.

## Проверки

`php tests/connection-migrations.php` выполняет реальные миграции только в изолированных SQLite-базах в памяти: выбор группы/БД, независимые обходы, частичный сбой, повторный запуск, откат, история, старые миграции, генерация файлов. Временные PHP-файлы создаются в `runtime` и удаляются после проверки.
