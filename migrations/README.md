# Миграции основной БД и баз курсов

Исходная схема заменена без переноса данных. На каждую таблицу приходится отдельная миграция. Старые пересекающиеся миграции удалены либо отредактированы; уже применённые миграции повторно не выполняются. Пересоздание существующих баз выполняет владелец проекта отдельно.

## Основная БД

`main/` содержит пользователей, каталог курсов, тарифы, скидки, платежи, подписки, слоты и профиль. Регистрация курса «Мой огород», импорт, валидатор импорта и исходные материалы удалены. Настройка подключения курса сама по себе не создаёт записи каталога или учебные данные.

```bash
php yii migrate
php yii migrate/create create_example_table
```

Команда по умолчанию использует основное подключение и папку `migrations/main`.

## Базы курсов

Миграции в `course/` наследуются от `BaseMigration` и возвращают группу `course` из `getConnections()`. История миграций ведётся отдельно в каждой базе. Без `--db` создаётся структура во всех подключениях группы; явный селектор должен входить в назначение миграции. Подробности — в [документации менеджера](../components/db/README.md).

```bash
php yii migrate-course
php yii migrate-course --db=course:moy_ogorod
php yii migrate-course/history --db=course:moy_ogorod
php yii migrate-course/create create_example_table
```

Команда `migrate-course` использует только `migrations/course`. При создании новых файлов назначение `getConnections()` необходимо добавлять вручную. Эквивалентный универсальный вызов: `php yii migrate --migrationPath=@app/migrations/course`.

Для нового курса добавьте подключение в `config/db/groups.php`. Таблицы не имеют префикса курса, все связи внутри учебной схемы локальны для его базы. `user_id` хранит идентификатор основной системы без межбазового внешнего ключа.

## Вопросы

- `question_pattern`: `id`, `pattern`. Вставки имеют вид `{{имя}}`, без типа.
- `question_answer_type`: `id`, уникальный `code`, `description`. Код выбирает обработчик ответа.
- `question`: `id`, `pattern_id`, `answer_type_id`, обязательный JSON `pattern_values`.
- `question_answer_option`: `id`, `question_id`, `value`.
- `question_right_answer`: `id`, `question_id`, обязательный JSON `answer`. Допускаются несколько правильных ответов на один вопрос.

Пример: паттерн `Как переводится слово {{word}}?`, значения `{"word":"apple"}`. Каждый ключ из паттерна обязан присутствовать в `pattern_values`. Строки подставляются буквально; другие JSON-значения выводятся как JSON, без специального форматирования. Содержимое вставки повторно как паттерн не обрабатывается.

Сохранены коды `choice_4_single`, `choice_multiple`, `input_text`, `ordering`. Категория интерфейса определяется обработчиком, отдельного поля `category` в типе ответа нет. Форматы правильных и пользовательских ответов:

```json
{"choice":[1,2]}
{"input":"текст"}
{"order":[2,1]}
```

Числа — идентификаторы вариантов вопроса; для `order` порядок значим. Пропуск хранится как SQL NULL в `active_test_answer.answer`.

## Единицы знаний и системы оценки

- `learning_item_type`: `id`, уникальный `key`, `description`.
- `learning_item`: `id`, `type_id`, `value`.
- `score_type`: `id`, `description`, `default_success_score`, `default_failure_score`.
- `question_score`: `id`, `question_id`, `learning_item_id`, `score_type_id`, nullable `success_score` и `failure_score`. Тройка вопрос/знание/система уникальна.
- `topic_learning_item`: `id`, `topic_id`, `learning_item_id`, `type` (`required` или `acquired`). Уникальна тройка тема/знание/роль.
- `user_learning_item_score`: `id`, `user_id`, `learning_item_id`, `completed_test_id`. Одна запись на пользователя, знание и завершённый тест.
- `user_score_value`: `id`, `score_id`, `score_type_id`, `total_score`, `success_score`, `failure_score`. Одна запись на оценку знания и систему.

Баллы — неотрицательные целые числа. Ноль является явным переопределением. NULL в поле `question_score` означает дефолт соответствующей системы. Если вопрос связан со знанием хотя бы в одной системе, при завершении начисляются баллы во всех существующих системах; отсутствие строки для системы также означает её дефолты.

Верный ответ начисляет `success_score` всем связанным знаниям; ошибка и пропуск — `failure_score`. Значения суммируются только в пределах завершённого теста, отдельно для каждой пары знание/система. `total_score = success_score + failure_score`: два успеха по 3 и ошибка на 2 дают 6, 2 и 8. База ограничивает знак, уникальность и равенство суммы.

Вопросы темы связываются через `topic_learning_item → learning_item → question_score` с ролью `acquired`. `required` предназначен для будущих рекомендаций тем; алгоритм рекомендаций пока отсутствует.

## Тесты и история

Сохраняются `category`, `topic`, `topic_lesson`, `test`, `test_category`, `active_test`, `active_test_question`, `active_test_answer`, `completed_test`. Порядок уроков — `position ASC, id ASC`; тесты удаляются флагом `is_deleted`.

`active_test_question.is_shown` устанавливается до выдачи вопроса. В `active_test_answer` сохраняются показанные варианты и их порядок (`presented_options`) и nullable ответ. Уникальная связь с вопросом попытки предотвращает дубли ответов.

`completed_test` содержит `id`, `user_id`, JSON `body`, `completed_at` в UTC. В снимке сохраняются текст вопроса, тип ответа, темы/категории, показанные варианты, ответ и `is_correct`. Баллы находятся в `user_score_value`; прежние общие поля баллов удалены.

Снимок, все оценки, удаление временных ответов и статус `passed` сохраняются одной транзакцией. Повторное завершение не создаёт статистику повторно. Отмена оценки не создаёт.

Старый подбор вопросов, учёт частоты и статистика по темам удалены. Запуск тестов временно возвращает HTTP 503. Новые рейтинги, графики, рекомендации и переключение системы оценки будут реализованы отдельно.

## Проверки без рабочей базы

`php tests/knowledge-schema.php` компилирует создание/откат MySQL DDL без подключения и проверяет схему, связи, уникальность и ограничения на SQLite в памяти. `php tests/active-test-handlers.php` проверяет ответы, начисление по всем системам, дефолты, повторные запросы и атомарность.

Дополнительные проверки: `tests/question-answer-type.php`, `tests/question-handlers.php`, `tests/right-answer-schema.php`, `tests/question-handler-schema.php`, `tests/migration-routing.php`, `tests/course-program.php`, `tests/dashboard.php`.

Старые проверки общей базы `learning-schema.php` и `course-api.php` не описывают текущую раздельную схему и не входят в этот набор.

## Подписки, платежи и слоты

По одной миграции на таблицу: `tariff`, `discount`, `payment`, `subscription`, `subscription_slot`.
Старые миграции `user_payment` и `user_subscription` удалены из исходного набора. Удаление этих таблиц в существующей БД и перенос данных выполняет владелец проекта самостоятельно; этот набор не является обновлением существующей базы.

- `discount.type`: `percent` (по умолчанию) или `amount`. Значение `DECIMAL(12,2)` больше нуля; для процентов максимум 100. Сумма скидки округляется до сотых, затем вычитается из цены. Итог не может быть отрицательным. Код одноразовый (`new` / `used`).
- `payment`: `id`, `user_id`, `tariff_id`, nullable `discount_id`, фактическая сумма `payment_amount`, дата `payed_at`. Название, лимит и длительность читаются из связанного тарифа, тип и значение скидки — из `discount`. Ключа повторного запроса пока нет.
- `subscription`: одна запись на пользователя (уникальный `user_id`), текущий `tariff_id`, оплаченный лимит слотов, `starts_at`, `expires_at`. Связи с платежом нет. Активность определяется по времени: `starts_at <= now < expires_at`.
- `subscription_slot`: подписка, курс, исходный `activated_at`, nullable `deactivated_at`. Отдельного срока окончания нет: доступ определяется сроком подписки и отсутствием деактивации. Повторная активация отключённого курса создаёт новую запись, сохраняя предыдущую для истории.

До первой оплаты записи подписки нет, сводка возвращает нулевые слоты. Первая оплата создаёт подписку, последующие обновляют ту же запись: тариф, лимит и срок с момента оплаты на `tariff.duration_days`. Активные слоты сохраняют дату активации. При уменьшении лимита отключаются последние активации: `activated_at DESC, id DESC` при одинаковом времени. Увеличение лимита не включает ранее отключённые курсы автоматически. При оплате после истечения подписки прежние слоты закрываются её прежней датой окончания; курсы можно активировать заново.

История платежей независима от текущего состояния подписки. Сведения о тарифе и скидке берутся из связанных таблиц; фактически оплаченная сумма хранится в платеже. Тарифы и скидки не удаляются, редактирование допускается для исправления ошибок. Название текущего тарифа берётся по `subscription.tariff_id`; изменение справочника не меняет ранее оплаченный срок и лимит подписки.

Платёж, погашение промокода, обновление подписки и деактивация лишних слотов выполняются в одной транзакции. Оплата и активация блокируют строку пользователя, чтобы параллельные запросы не превысили лимит. Каждый успешный запрос оплаты создаёт отдельный платёж; защита от повторной обработки будет добавлена при подключении платёжной системы. Повторная активация действующего курса возвращает прежний слот. При смене тарифа стоимость уменьшается на остаток активной подписки, если он строго больше 100 ₽; неполный оставшийся день округляется вверх, итог не ниже нуля. В платёж записывается фактическая доплата. Дополнительные поля БД для перерасчёта не требуются. Текущая оплата — заглушка без платёжного провайдера.
