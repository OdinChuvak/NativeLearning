# Миграции основной БД и баз курсов

Команда `migrate` поддерживает выбор подключений внутри миграции через `BaseMigration::getConnections(): ?ConnectionGroup`: группу (в том числе из одной БД) либо `null` для подключения команды по умолчанию. История ведётся отдельно в каждой БД. Описание и примеры — в [документации менеджера](../components/db/README.md).

Это исходная схема для раздельных БД, а не автоматический переход со старой общей базы. Все применения, откаты и перенос данных выполняет владелец проекта. Уже применённые миграции после редактирования не выполнятся повторно.

## Основная БД

`main/` содержит пользователей, каталог курсов, общий рейтинг, тарифы, скидки, платежи, подписки, слоты и запись курса «Мой огород».

```bash
php yii migrate
php yii migrate/create create_example_table
```

Команда использует `config/db/db.php` и только папку `migrations/main`.

## База курса

Все существующие миграции в `course/` наследуются от `BaseMigration` и явно возвращают группу `course` из статического `getConnections()`. Поэтому `php yii migrate-course` без `--db` выполняет их во всех БД группы, а явный `--db=course:moy_ogorod` ограничивает выполнение одним разрешённым подключением. Новые файлы по-прежнему генерируются стандартными: это назначение нужно добавлять вручную.

Короткая команда для одного курса:

```bash
php yii migrate-course --db=course:moy_ogorod
php yii migrate-course/history --db=course:moy_ogorod
php yii migrate-course/create create_example_table
```

Она использует директорию `migrations/course`; указание другой директории через `--migrationPath` или `-p` вызывает исключение. Явный `--db` выбирает подключение только в пределах назначения `getConnections()`; несовпадение вызывает исключение до выполнения набора. Без назначения миграции используется подключение команды. Для всей группы используйте `php yii migrate-course --db=course`.

`course/` — единый набор миграций для всех курсов: `question_type`, `category`, `topic`, `question`, `answer_option`, `question_topic`, `test`, `test_category`, `active_test`, `active_test_question`, `active_test_answer`.

```bash
php yii migrate --db=course:moy_ogorod --migrationPath=@app/migrations/course
php yii migrate/create create_example_table --migrationPath=@app/migrations/course
# Все базы группы:
php yii migrate --db=course --migrationPath=@app/migrations/course
```

В универсальной команде `migrate` подключение выбирается через `--db` из зарегистрированных компонентов; неизвестное имя приводит к ошибке до выполнения миграций. Получение подключения не требует запроса к каталогу курсов основной БД.

Для нового курса добавьте файл подключения и зарегистрируйте его в группе `course` в `config/db/groups.php`. В универсальной команде `migrate` доступны стандартные параметры `--db`, `--migrationPath`, `--migrationNamespaces` и сокращение `-p`. Явный `--db` проверяется на соответствие назначению миграции, а без этого параметра назначение выполняется целиком.

Каждая БД хранит собственную историю в таблице `migration`. Создание файла в `migrations/course` добавляет миграцию в общий набор курсов; каждая выбранная база применяет её отдельно.

## Связи и перенос

Таблицы курса имеют имена без префикса `course_sample_` или `course_moy_ogorod_`. `category` не содержит `course_id`. `test_category` связывает локальные `test` и `category`, первичный ключ — `(test_id, category_id)`. `test.user_id` хранит ID пользователя основной системы без внешнего ключа.

В основной таблице `user_rating` добавлен `course_id` с внешним ключом на каталог и включён в первичный ключ: локальные ID разных курсов могут совпадать. Внешние ключи рейтинга на темы и вопросы попыток удалены. Это ещё не реализация передачи результатов или защиты outbox от повторного начисления.

Миграция `m260915_000001_create_moy_ogorod_course` теперь только регистрирует курс в каталоге. Материалы в `data/courses/moy_ogorod` сохранены; загрузка в новую БД будет отдельным этапом. `migrations/support/MoyOgorodData.php` оставлен как валидатор исходных материалов, команда миграций его не запускает.

Сервисы и существующая рабочая БД пока используют прежнюю схему. Этот набор сам по себе не переключает приложение, не переносит сохранённые тесты и не удаляет старые таблицы. История прохождений и outbox пока не добавлены.

## Проверка без БД

```bash
php tests/migration-routing.php
```

Проверяет регистрацию менеджера, выбор группы/подключения, параметры единой команды и разделение файлов. Не подключается к БД и не выполняет миграции. `php tests/connection-migrations.php` дополнительно проверяет реальные запуски и отдельную историю на SQLite в памяти.

Старые интеграционные проверки `learning-schema.php`, `course-api.php`, `moy-ogorod.php` рассчитаны на общую схему и прежний импорт; их адаптация относится к переключению приложения на базы курсов. Не используйте их для проверки новой раздельной схемы.

## Подписки, платежи и слоты

По одной миграции на таблицу: `tariff`, `discount`, `payment`, `subscription`, `subscription_slot`.
Старые миграции `user_payment` и `user_subscription` удалены из исходного набора. Удаление этих таблиц в существующей БД и перенос данных выполняет владелец проекта самостоятельно; этот набор не является обновлением существующей базы.

- `discount.type`: `percent` (по умолчанию) или `amount`. Значение `DECIMAL(12,2)` больше нуля; для процентов максимум 100. Сумма скидки округляется до сотых, затем вычитается из цены. Итог не может быть отрицательным. Код одноразовый (`new` / `used`).
- `payment`: `id`, `user_id`, `tariff_id`, nullable `discount_id`, фактическая сумма `payment_amount`, дата `payed_at`. Название, лимит и длительность читаются из связанного тарифа, тип и значение скидки — из `discount`. Ключа повторного запроса пока нет.
- `subscription`: одна запись на пользователя (уникальный `user_id`), текущий `tariff_id`, оплаченный лимит слотов, `starts_at`, `expires_at`. Связи с платежом нет. Активность определяется по времени: `starts_at <= now < expires_at`.
- `subscription_slot`: подписка, курс, исходный `activated_at`, nullable `deactivated_at`. Отдельного срока окончания нет: доступ определяется сроком подписки и отсутствием деактивации. Повторная активация отключённого курса создаёт новую запись, сохраняя предыдущую для истории.

До первой оплаты записи подписки нет, сводка возвращает нулевые слоты. Первая оплата создаёт подписку, последующие обновляют ту же запись: тариф, лимит и срок с момента оплаты на `tariff.duration_days`. Активные слоты сохраняют дату активации. При уменьшении лимита отключаются последние активации: `activated_at DESC, id DESC` при одинаковом времени. Увеличение лимита не включает ранее отключённые курсы автоматически. При оплате после истечения подписки прежние слоты закрываются её прежней датой окончания; курсы можно активировать заново.

История платежей независима от текущего состояния подписки. Сведения о тарифе и скидке берутся из связанных таблиц; фактически оплаченная сумма хранится в платеже. Тарифы и скидки не удаляются, редактирование допускается для исправления ошибок. Название текущего тарифа берётся по `subscription.tariff_id`; изменение справочника не меняет ранее оплаченный срок и лимит подписки.

Платёж, погашение промокода, обновление подписки и деактивация лишних слотов выполняются в одной транзакции. Оплата и активация блокируют строку пользователя, чтобы параллельные запросы не превысили лимит. Каждый успешный запрос оплаты создаёт отдельный платёж; защита от повторной обработки будет добавлена при подключении платёжной системы. Повторная активация действующего курса возвращает прежний слот. При смене тарифа стоимость уменьшается на остаток активной подписки, если он строго больше 100 ₽; неполный оставшийся день округляется вверх, итог не ниже нуля. В платёж записывается фактическая доплата. Дополнительные поля БД для перерасчёта не требуются. Текущая оплата — заглушка без платёжного провайдера.
